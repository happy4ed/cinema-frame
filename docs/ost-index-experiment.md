# OST 전곡 색인 실험 — 2026-11-08

사용자 정정에 따라 **영화 장르·키워드·Wikidata 음악 주제로 후보를 제한하지 않는다.** 이전 Wikidata 음악 스타일 수집은 중단했고 앱에 적용하지 않았다. 기존 태그 사전과 비교 도구는 보존했다. `4b08659`는 `feature/ost-top3-country`에 푸시했다.

## 표본 및 측정 기준

- 기존 로컬 IMDb 카탈로그의 투표 수 내림차순 상위 200편. 동률은 평점 내림차순, IMDb ID 순. 기존 사용자 국가 제외인 IN은 유지했다. 음악 장르·영화 장르·시대 제한 없음.
- TMDB 인기 목록 API 연결은 실제 성공했다. 표본은 중간에 바꾸지 않고 기존 카탈로그 200편으로 고정했다. 이번 실험에서 TMDB는 IMDb 영화 ID와 음악 크레딧을 대조하는 데 사용한다.
- 영화마다 Deezer 앨범을 검색하고 전곡을 읽는다. 영화별 top3, Spotify 재생 검증은 **판단 기준 선정 후 구현 단계**이며 이번 분류 실험의 곡 수를 줄이지 않는다.
- `rank`, `isrc`, 아티스트, 영화/앨범 연결 및 수신 시각을 보존한다. 같은 Deezer track ID는 중복 제거하고 여러 영화와 연결된 경우 영화 목록을 보존한다. 서로 다른 Deezer ID가 같은 ISRC를 가질 수 있어 두 수치를 구분한다.
- 아티스트 태그 포함 비율은 **고유 아티스트 기준**과 **해당 아티스트가 연결된 곡 기준**을 각각 보고한다.
- 기존 `config/music-tags.json`을 변경하지 않고 재즈 하위 장르 및 분위기 동의어를 그대로 쓴다. 다른 스타일의 보조 버킷은 사용자가 명시한 `classical`, `rock`, `pop`, `electronic`, `orchestral / orchestral score`의 정확한 태그만 사용한다. 개인 분류 태그는 선택 근거가 아니다.
- 태그는 응답 순서를 보존하며 양수 count 또는 count 필드가 없는 명시적 태그를 사용한다. 아티스트에서 스타일이 판단되면 우선하고, 없으면 곡 태그를 사용한다. 분위기도 같은 순서다. 둘 중 미판정 항목이 있을 때만 Gemini에 보내고, 태그로 이미 판단된 항목을 Gemini로 덮어쓰지 않는다.
- Gemini 입력에는 영화·곡·아티스트와 고유 키만 보내고 태그 정답을 알려주지 않는다. 모델은 계정에서 제공이 확인된 `gemini-2.5-flash`. 30곡씩 묶고 요청 시작 간격 15초. `unknown`은 빈 스타일·분위기로만 허용한다. 누락/중복 키·잘못된 JSON·API 오류는 중단한다.
- 별도 검증 50곡은 아티스트 태그로 재즈인 곡 25개와 다른 스타일 곡 25개를 가능한 만큼 고르고, 부족분은 나머지에서 채운다. 고정 해시 순서로 재현 가능하며 사람이 곡을 고르지 않는다. Gemini에는 아티스트 태그를 숨긴다. **태그와의 일치율은 실제 음악에 대한 정확도가 아니다.**
- 캐시는 출처·수신 시각·7일 만료를 기록한다. 중간 상태를 저장해 재개한다. 이 도구는 호스트 실험용이며 프레임의 매일 백그라운드 갱신 기능은 아직 구현하지 않았다.

## 실험 전 발견한 앨범 연결 오류

기존 `album_matches`의 제목+OST 표기만으로는 잘못된 연결이 발생했다. 실제 초기 응답에서 The Dark Knight는 Imperial Orchestra의 라이브 1곡, Inception은 Lalit Thapa의 동명 1곡, Fight Club은 OG RIP의 다른 작품 곡을 선택했다. 이 실행은 폐기하고 결과 통계에 사용하지 않는다. 원문은 `work/ost-index-experiment/rejected-title-only-checkpoint.json` 및 캐시에 보존했다. **기존 앱의 앨범 매칭도 같은 약점이 있으며 이번 실험 중 앱은 수정하지 않았다.**

정식 실험에서는 영화명 정확 일치·OST 표기에 더해 TMDB에서 IMDb로 식별한 영화의 `Original Music Composer`와 Deezer 앨범 아티스트를 대조한다. Various Artists 앨범이면 수록곡 아티스트 중 작곡가 연결을 확인한다. 라이브·커버·재녹음 표기는 제외한다. 작곡가 근거가 없거나 일치하지 않으면 사유와 함께 건너뛴다.

이 검증은 동명 다른 영화와 명백한 재연주를 줄이지만 **발매 권리자의 독립적인 공식 인증은 아니다.** 작곡가가 수록곡에 없는 편집형 OST, 번역/축약 앨범명, 다른 아티스트 표기는 누락될 수 있다. 따라서 결과는 인기 200편 전체의 모든 OST를 완전히 확보했다는 뜻이 아니다.

## 실제 결과

| 항목 | 결과 |
|---|---:|
| 조사한 인기 영화 | 200편 |
| 제목·음악 크레딧 연결을 통과한 OST 앨범 | 81개 (40.5%) |
| 수록곡 / 고유 Deezer track ID / 고유 ISRC | 각각 1,779개 |
| 아티스트 태그가 있는 아티스트 | 118/123명 (95.9%) |
| 아티스트 태그가 연결된 곡 | 1,754/1,779곡 (98.6%) |
| 개별 곡 태그가 반환된 곡 | 4/1,779곡 (0.2%) |
| 아티스트 태그만으로 재즈로 분류 | 106곡 |
| 아티스트 태그 상위 5개만 사용한 재즈 분류(오프라인 비교) | 66곡 |
| 곡 태그 단계까지 적용한 재즈 분류 | 106곡 |
| 미판정 항목을 Gemini로 보충한 뒤 재즈 분류 | 107곡 |
| 보충 대상으로 보낸 곡 / Gemini 모름 | 704곡 / 117곡 |

119편은 앨범이 없다고 단정한 것이 아니다. 109편은 제한된 검색과 크레딧 대조에서 앨범 연결을 확인하지 못했고, 10편은 TMDB 음악 크레딧이 없었다. 검색은 영화 원제+soundtrack, 영화 원제+첫 번째 음악 크레딧의 두 쿼리, 각 최대 100개 앨범 결과다. **200편의 모든 OST를 확보한 실험은 아니며, 위 비율은 확보한 81개 앨범에 대한 값이다.**

곡 태그는 Deezer에서 받은 아티스트·곡명 그대로 `autocorrect=0`으로 조회했다. 따라서 4곡이라는 수치는 다른 표기·녹음 ID로 조회해도 태그가 없다는 뜻이 아니다. 이번 사전의 태그 count는 임계값으로 줄이지 않았고 응답에 count가 없는 명시적 태그도 보존했다.

Gemini가 추가한 재즈 1곡은 *Whiplash — Snare Liftoff - I Want to Be One of the Greats*다. 응답 이유는 “이 곡은 영화 '위플래쉬'의 대사와 재즈 드럼 연주가 포함된 강렬한 트랙입니다.”였다. **이유는 Gemini 판단이며 청취로 검증한 사실이 아니다.** Gemini `unknown`인 모든 곡을 제외해서 다시 집계해도 재즈 수는 107곡으로 같았다.

## 50곡 비교

아티스트 태그로 재즈인 곡 25개 + 다른 스타일 곡 25개, 총 22명 아티스트·26편 영화의 고정 해시 표본이다. 전체 색인의 자연 비율을 그대로 대표하는 표본은 아니다. Gemini는 48곡을 판단하고 2곡을 모름으로 반환했다.

| 비교 기준 | 판단 가능한 48곡 기준 |
|---|---:|
| 재즈 여부 일치 — 아티스트 태그 전체 | **31/48 (64.6%)** |
| 재즈 여부 일치 — 아티스트 태그 상위 5개만 | **40/48 (83.3%)** |
| 양쪽 모두 재즈 | 8곡 |
| 아티스트만 재즈, Gemini는 재즈 아님 | 17곡 |
| 양쪽 모두 재즈 아님 | 23곡 |
| Gemini만 재즈 | 0곡 |
| 전체 스타일 집합 완전 일치 | 5/48 (10.4%) |
| 스타일 중 하나 이상 겹침 | 27/48 (56.3%) |

Gemini 모름 2곡을 분모에 포함해 '일치가 확인된 곡'으로 표현하면 전체 태그 31/50, 상위 5개 40/50이다. 이를 정답률이라고 부르지 않는다. Gemini 자체도 틀릴 수 있으며, 실제 음원을 청취해 정답 라벨을 만든 실험은 아니다.

대표적인 불일치는 *Psycho*의 Bernard Herrmann, *Knives Out*의 Nathan Johnson 곡들이다. 아티스트에 재즈 태그가 있지만 Gemini는 개별 곡을 오케스트라 스코어로 분류했다. 같은 작곡가의 여러 곡이 표본에 포함돼 있어 일반화에도 주의가 필요하다. 아티스트 상위 5개만 쓰면 Herrmann 사례는 줄지만 Nathan Johnson 사례는 남는다. **아티스트 태그가 풍부하다는 사실과 곡 장르를 그대로 확정해도 된다는 판단은 별개다.** 기준은 사용자 확정 전이다.

## 호출·시간·실패

| API | 정식 측정 HTTP 호출 |
|---|---:|
| Deezer | 346회 |
| Last.fm | 1,899회 |
| TMDB | 400회 |
| Gemini | 27회 (실패 2회 포함) |
| 합계 | **2,672회** |

Deezer 캐시 사용 48회, Last.fm 캐시 사용 3회. Last.fm은 실제 임의 1초 구간 최대 **5회**였다. 프로세스 실행 시간 합계 **1,264.3초 (21분 4초)**, 요청 형식 수정 시간을 포함한 첫 실행부터 마지막 완료까지 **1,390.2초 (23분 10초)**다. 연결 확인·폐기한 제목 단독 매칭 진단은 이 정식 측정 수치에 포함하지 않았다. 실패한 요청 형식과 재개 실행은 포함했다.

Gemini 20번째 요청은 입력에 없는 키 또는 중복 키를 반환해 해당 묶음을 버렸다. 최초 실패 응답 원문은 저장되지 않았고 어느 키가 잘못됐는지까지는 확인할 수 없다. 검증 오류와 호출 기록은 보존했다. 이어 식별자별 객체 스키마는 너무 복잡하다는 HTTP 400으로 거절됐다. 단순 배열 스키마에 허용된 키 enum을 추가한 뒤 실패 묶음부터 재개했고, 모든 최종 답변의 키 일치·중복·누락·unknown 빈 레이블을 검사했다. 이후 응답은 검증 전에 원문부터 저장하도록 보완했다. 잘못된 응답을 데이터로 채택하거나 곡 제목으로 대체하지 않았다.
